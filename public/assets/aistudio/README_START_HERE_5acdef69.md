# Growth OS Kazakhstan — обновление UX v3

## Что внутри

1. `GEMINI_UPGRADE_PROMPT_v3.md` — подробное техническое задание на исправление вашего **существующего** React/Vite-проекта.
2. `enriched_237_tasks.json` — расширенные инструкции по всем 237 задачам: 897 пошаговых инструкций, роли, критерии, примеры и применимые проверенные публичные ссылки.
3. `verified_resources.json` — проверенные официальные организации/источники на 28.10.2026, ссылки, отдельные подтверждённые публичные контакты и предупреждения об отсутствии контактов.
4. `dashboard_prototype.html` — открываемый в браузере мобильный интерактивный UX-макет кругов прогресса с демонстрационными задачами; **не** связано с вашей реальной CRM.

## Как использовать в Google AI Studio Build Mode

**Если Gemini уже содержит проект:** откройте тот же проект. Сначала экспортируйте резервную копию данных в текущем Growth OS через экран «Настройки → Экспорт» (если его экспорт действительно работает). Сохраните рабочий исходный ZIP проекта и этот JSON-бэкап на своём устройстве. Прикрепите `GEMINI_UPGRADE_PROMPT_v3.md`, `enriched_237_tasks.json`, `verified_resources.json` и `dashboard_prototype.html` к проекту/встроенному чату (если прикрепление поддерживается). Скажите «Реализуй изменения v3 в текущем коде, не создавая новый проект; делай по этапам и проверяй реальную сохранность».

**Если создаёте новый проект из ZIP:** сначала импортируйте `growth-os-kazakhstan.zip`, затем пакет v3. Объясните Gemini, что исходный код — источник истины для текущего проекта, а файлы v3 — миграция интерфейса и объяснений задач, а не новая база клиентов.

## Чего пакет НЕ делает

- Это **не** готовый исправленный production-код приложения: архив — ТЗ, данные и дизайн-референс для Gemini Build Mode.
- Не содержит доступов к Meta Ads, номеру WhatsApp, налоговой, банку, Google или серверам.
- Не подтверждает выполненные задачи, реальные продажи, одобренные мероприятия или наличие кабинета в Hub.
- Не синхронизирует локальные данные между телефоном основателя и супруги без защищённого серверного backend.
- Инструкции ко всем 237 задачам подготовлены на основе названий, направлений и публичных источников; специфичные бизнес-решения, время и цены нужно подтвердить лично. Во внутренних задачах ссылки не нужны.

## Отдельно проверить после обновления

- Реальный прогресс **не должен** стартовать с 8 автоматически выполненных seed-задач.
- Выдуманные бизнесы, агенты и партнёры **не должны** попадать в реальную CRM.
- `2026-10-28` не должен оставаться «сегодня» на следующий день.
- Нельзя показывать «уведомление отправлено», если никакое уведомление не отправлялось.
- Проверить неизменность IDs для всех 237 задач, сохранение уже выполненного и экспорт/импорт бэкапов.

## Результат, к которому стремимся

Рабочий мобильный центр управления: кольцевые индикаторы направлений и всего плана; проекты → этапы → понятные задачи; конкретные источники/контакты/шаблоны; двое исполнителей; контроль сроков и бюджетов; коммерческая аналитика только из фактов.
